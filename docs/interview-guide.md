# 项目讲解与动手练习

## 一分钟介绍

我做了一个 AI 智能伴侣项目，原型支持昵称和性格配置、多轮流式对话，以及 JSON 会话保存和管理。后来在 AI 编程工具辅助下，我把它整理成模块化项目，并补了对话数据处理流程：校验格式和轮次，脱敏、去重，导出 JSONL，同时生成质量报告和来源追踪。这个项目让我把 LLM 应用和数据准备联系起来。目前它是单机原型，验证了程序和数据规则，还没有进行模型微调或真实回答效果评测。

## 应该能解释的六个问题

1. 一份会话 JSON、一条消息和一条训练样例分别代表什么？为什么一段两轮会话能产生两条样例？
2. 为什么用户和 assistant 必须交替，最后只有用户输入的会话为什么不导出？
3. 同一会话有重叠上下文，按消息随机划分为什么可能泄漏？当前方法还漏掉哪些相似会话？
4. 脱敏覆盖哪些信息？为什么正则脱敏不代表可以直接公开任意真实数据？
5. API 超时或流式回复中断时，界面显示与保存数据如何处理？
6. 本人原来做了什么，本次 AI 辅助补了什么，目前能独立修改哪几处？

## 两天可完成的学习任务

第一天 60 分钟：运行离线界面，完成新建、聊天、保存、加载、删除；打开保存的 JSON，画出一行数据的含义。然后运行样例处理，逐项对照质量报告的 6 类拒收原因。

第二天 60 分钟：自己新增一份合法合成会话和一份错误样例，先预测输出计数再运行核对。修改一条脱敏规则或角色提示词，重跑测试，并解释影响范围。

能复述 README 只是起点；能够实际运行、修改、解释一次失败和验证结果后，再在面试中使用更强的熟练度表述。
